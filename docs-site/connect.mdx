The hosted server is **`https://thingery.dev/mcp`**. Pick your client: it finds the sign-in flow on its own, you approve once in the browser, and its tokens rotate automatically.

You can review and revoke connected apps at [thingery.dev/apps](https://thingery.dev/apps). A self-hosted instance works the same way at its own URL.

## Claude custom connector: which sign-in option

When you add Thingery as a custom connector, Claude asks how it should authenticate. It may preselect **No sign-in**, because search works without an account. Change it:

| Option | Use it when |
|---|---|
| **Sign in when needed** | Recommended. Search works right away; Claude opens the sign-in the first time you list, order or save a search |
| **Sign in now** | You know you will sell or buy. You sign in before the first tool call |
| **No sign-in** | Search only, or with an API key: add a request header `Authorization` with the value `Bearer thg_YOUR_KEY`. Without a key, every tool that needs an account fails with `401` |

Claude does not let you change this after adding the connector: to switch, remove it and add it again.

Under **OAuth client**, keep **Use Claude's published identity**. **Register automatically** works too. Leave **Request headers** empty: with sign-in, Claude sends the token itself.

Keep the transport on **Streamable HTTP**. Thingery does not serve the legacy SSE transport.

## MCP Inspector

```bash
npx @modelcontextprotocol/inspector
```

Choose the **Streamable HTTP** transport, enter `https://thingery.dev/mcp` and connect. The Inspector offers the sign-in.

## Use an API key instead

Scripts, CI and clients without OAuth send an API key as a bearer token. See [Authentication](/authentication) to get one.

```json
{
  "mcpServers": {
    "thingery": {
      "type": "http",
      "url": "https://thingery.dev/mcp",
      "headers": { "Authorization": "Bearer thg_YOUR_KEY" }
    }
  }
}
```

Leave out the `Authorization` header to use only the public tools, such as search.

## Local server over stdio

The [`thingery` npm package](https://www.npmjs.com/package/thingery) also runs as a local stdio server against your own Postgres. See [Self-hosting](/self-hosting/install#run-over-stdio).

## Plain HTTP

No client is needed. List the tools:

```bash
curl -s https://thingery.dev/mcp \
  -H 'content-type: application/json' \
  -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

The `accept` header is required by the transport; without it the server answers `406`.

- [`llms.txt`](https://thingery.dev/llms.txt): the endpoint and tool reference for language models.
- [`/.well-known/agents.json`](https://thingery.dev/.well-known/agents.json): the agent capabilities manifest.
